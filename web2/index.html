Docker Compose | Project Implementation

Building a Multi-Container Application

A practical demonstration of building and running two web applications together using Docker Compose.

01. Project Objective

The objective of this project was to run two different web applications in separate Docker containers and manage both using Docker Compose.

02. Project Structure

I created two directories, web1 and web2. Each directory contains an index.html file and its own Dockerfile. I also created a Compose YAML file in the main project directory. 

My-project/
│
├── compose.yml
│
├── web1/
│   ├── index.html
│   └── Dockerfile
│
└── web2/
    ├── index.html
    └── Dockerfile

03. Dockerfiles

Each Dockerfile contains the instructions required to build the image for its respective web application. This keeps the configuration of Web1 and Web2 independent.

04. Compose YAML Configuration

In the Compose file, I defined two services and specified their build directories. Docker Compose uses these build contexts to locate the respective Dockerfiles. 

services:
  web1:
    build: ./web1
    ports:
      - "8081:80"

  web2:
    build: ./web2
    ports:
      - "8082:80"

The port mappings above are examples. They must match the ports configured in your actual Compose file and web servers.

05. Build and Run

From the main project directory, I executed:

docker compose -f compose.yml up --build -d

This command builds the images and starts both services in detached mode.

To verify the running containers:

docker compose -f compose.yml ps

06. Final Outcome

  • Created two independent web applications.
  • Built a separate Docker image for each application.
  • Configured both services in one Compose YAML file.
  • Started both containers using one command.
  • Simplified multi-container application management.
